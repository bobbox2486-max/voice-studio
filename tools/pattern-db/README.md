# 型データベース（pattern-db）

お手本1本ではなく、**多数の動画から測った「型」の分布**を蓄積する場所。
「AIのいいところは、人間に出来ない量の学習データ」（ボブ方針）に基づき、
自然な抑揚の基準は1話者の値ではなく、複数話者・複数動画の統計
（中央値・四分位）で持つ。

## 方針

- **まずは日本語を確実に固める**（2026-11-18 ボブ方針）。多言語は
  将来の視野に置くが、今は日本語以外に手を広げない。
- 設計だけ言語対応にしておく：`pattern-db/<lang>/` のフォルダ分けと、
  manifest / index への `lang` フィールド。言語を増やすときは
  フォルダと manifest の追加だけで済む形にする。

## 構成

- `build_index.py`：manifest → index.json（動画ごとの型）＋
  aggregate.json（ジャンル別／全体の分布統計）の取り込み・集計。
- `<lang>/manifest.json`：取り込み対象（動画ID・ジャンル・metrics の場所）。
- `<lang>/index.json`：動画ごとの型プロファイル。
- `<lang>/aggregate.json`：分布の要約（n・中央値・四分位・最小最大）。

## 蓄積の計画（日本語）

1本あたりの分析は実測で数分。バッチで回せば一晩で数十本が処理できる。

- **Phase A（土台固め）**：合計50本を目標にする。
  - 読み聞かせ・朗読：25本（絵本・朗読。話者・男女・年代を分散）
  - トーク・雑談：15本（VTuber雑談・ラジオ的トーク等）
  - ナレーション・解説：10本（ゆっくり解説・ニュース読み等）
  - 開始時点の実績：3本（読み聞かせ2・トーク1）。音声抽出ボードの
    登録素材と追加探索で候補を埋める。
- **Phase B（分布の確定）**：合計150〜200本まで広げ、ジャンル別の
  「自然な範囲」（文のピッチ変化・抑揚の幅・文末比率・話速・間の
  分布）を統計として確定する。類似度スコアの物差しも、この分布
  基準に置き換えていく。
- 運用：候補リスト → video_analyzer.py をリスト駆動でバッチ分析 →
  manifest に追記 → build_index.py で集計を更新、を定例化する。

## 使い方

```bash
# manifest に動画を足してから
python3 build_index.py --lang ja
```

## 現時点の観察（ja・3件時点の暫定）

- 読み聞かせ2話者の文ピッチ変化の中央値は −0.28 / −1.40 半音、
  トーク1件は −2.86 半音。一方 local TTS の素の文末降下は −11 半音級で、
  測った全話者の範囲の外にある（＝土台側の癖が大きいことの傍証）。
  件数が増えれば「自然な範囲」を分布として言い切れるようになる。
