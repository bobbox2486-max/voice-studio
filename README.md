# voice-studio

**簡単な入口 × 細かいカスタム ＝「この声が欲しかった」**

お手本の声（動画・音声）から「読みの型」（話速・間・ピッチ）を抽出し、
自前の声をその型に近付けて生成する音声カスタムシステム。
ゲームのキャラクリのように、キャラを選んでステータス（高さ・速さ・
間・強弱）を調整し、キャラシートとして保存・再利用できる形を目指す。

## リポジトリ構成

- `tools/video_analyzer.py` — 測定側：YouTube動画から読みの型を定量化する
- `docs/` — 設計メモ
- `tools/voice_adjust.py` — 生成側（キャラクリ方式の音声調整）。
  ※現在、抽出→近付けループの強化を編集中のため未収録。
  ループ完成時にまとめて追加する。

以下は tools の README（測定側・生成側の使い方）です。

# video_analyzer.py — YouTube動画の音声抽出＋読み分析ツール

YouTube動画のURLを渡すだけで、「読み」の型を定量化したMarkdownレポートを
生成する単体CLIツールです。日本語の読み聞かせ／トーク動画を繰り返し測定し、
同じ物差しで比較する（ベンチマーク分析）ために作られました。

測定項目：文の数と長さ、読み速さ（全体／発話内）、文間の「間」の分布、
タイトルコール後の間と締めの余韻、F0（ピッチ）の相対統計
（地の文とセリフの高さの差、文末の上がり下がり）など。

## 前提・動作環境

- Python 3.10以上（開発・検証は 3.12）
- ffmpeg（音声変換に必須。`ffmpeg -version` で確認できること）
- YouTubeへアクセスできるネットワーク
- 音声とモデルで数百MB程度の空きディスク

## 依存の導入

Pythonパッケージは pip のユーザー領域インストールを想定します
（PEP 668 環境では `--break-system-packages` が必要です）。

```bash
python3 -m pip install --user --break-system-packages yt-dlp praat-parselmouth faster-whisper
```

- `yt-dlp`：動画メタ情報・字幕・音声の取得
- `praat-parselmouth`：F0（基本周波数）の抽出（Praat の Python バインディング）
- `faster-whisper`：字幕に単語時刻がない場合の、音声認識による単語
  タイムスタンプ復元（後述）。CPU推論のみで動作します

### faster-whisper のモデル配置

初回はモデル（base で約145MB）が自動ダウンロードされます。
環境によっては Hugging Face Hub からの自動取得が失敗することがあります。
その場合は手動で取得し、`~/.cache/faster-whisper/base/` に配置してください
（ツールはこの場所に model.bin があれば自動でそちらを読みます）。

```bash
mkdir -p ~/.cache/faster-whisper/base
cd ~/.cache/faster-whisper/base
BASE=https://huggingface.co/Systran/faster-whisper-base/resolve/main
for f in config.json tokenizer.json vocabulary.txt preprocessor_config.json model.bin; do
  curl -L -o $f $BASE/$f
done
```

モデルを変える場合は `--whisper-model` で名前（tiny/base/small/medium）や
ローカルパスを指定できます。大きいモデルほど精度が上がりますが遅くなります。

## 使い方

```bash
# 基本：URLでも動画IDでもよい
python3 video_analyzer.py https://www.youtube.com/watch?v=gLv9_04OUyI
# → ./analysis-output/gLv9_04OUyI/report.md と metrics.json が生成される

# 出力先の指定
python3 video_analyzer.py gLv9_04OUyI --out ./test-output/gLv9_04OUyI

# 字幕・音声などの中間ファイルも残す（デバッグ用）
python3 video_analyzer.py <URL> --keep-work

# 日本語字幕がない動画（歌ってみた等）：既定の --asr auto で音声全体の
# 書き起こしに自動フォールバックする（レポートにASR由来と明記される）
python3 video_analyzer.py https://www.youtube.com/watch?v=oK6JtW0KuAc
```

### 主なオプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `--out DIR` | `./analysis-output/<動画ID>/` | レポート出力先 |
| `--ytdlp PATH` | 自動探索 | yt-dlp 実行ファイルのパス（PATH、`~/.local/bin`、Pythonモジュールの順に探す） |
| `--player-client NAME` | `android` | yt-dlp の YouTube プレイヤークライアント。環境により「動画が取得できない」場合に変更。空文字で指定なし |
| `--whisper-model NAME` | `base` | faster-whisper のモデル名またはローカルパス |
| `--asr MODE` | `auto` | 音声認識の使い方（下記「ASRモード」参照）。`auto`／`always`／`never` |
| `--no-asr` | 無効 | 音声認識を使わず字幕ウィンドウ内分で近似（精度が落ちる。`--asr never` と同じ） |
| `--work-dir DIR` | 一時ディレクトリ | 中間ファイル置き場（指定時は削除しない） |
| `--keep-work` | 無効 | 中間ファイル（字幕・WAV）を作業ディレクトリに残す |

### ASRモード（`--asr`）

音声認識（faster-whisper）の使い方を指定します。

- `auto`（既定）：字幕に単語時刻が無い場合は単語タイムスタンプの復元に
  音声認識を使い（従来動作）、**日本語字幕自体が存在しない場合は音声全体の
  書き起こしにフォールバック**します。この場合、文面と時刻の土台は
  すべて書き起こし由来になり、レポートと metrics.json に
  `align_mode: "asr_full"`／`text_source: "asr"` と明記されます。
  字幕あり動画の挙動は従来と変わりません。
- `always`：日本語字幕があっても、常に音声全体の書き起こしを土台にします
  （`align_mode: "asr_full"`）。
- `never`：音声認識を使いません。字幕がなければ終了コード4で失敗し、
  字幕に単語時刻がなければ字幕ウィンドウ内分で近似します（`--no-asr` と同じ）。

なお全文書き起こし経路（`asr_full`）では、VAD（音声区間検出）を無効化して
います。VADは歌唱の持続発声を非音声として大量に落としてしまうためです
（歌動画で単語数が桁違いに減ることを実測で確認）。metrics.json の
`asr_vad_filter` に使用した設定が記録されます。

## 出力

出力先ディレクトリに2ファイルができます。

- `report.md`：人間が読むレポート。構成は
  「1. 方法と制約（正直な限界）／2. 字幕ベースの測定（文の長さと速さ・間・
  文末表現・導入と締め）／3. F0分析／4. サマリー表」。
- `metrics.json`：同じ測定値を機械可読にしたもの（再集計・比較用）。
  数値の出所を示すフィールドとして `align_mode`（caption／asr／window／
  asr_full）、`text_source`（captions／asr）、`asr_mode`、
  `asr_vad_filter`、`subtitle_kind`／`subtitle_lang` が入ります。
  **字幕由来とASR由来の数値は出所が違うため、横比較ではこれらの
  フィールドを必ず確認してください。**

## 終了コードとエラーの対処

失敗時は理由と「／対処: …」が標準エラーに出力され、以下のコードで終了します。
メッセージの対処を読めば、利用者が次の行動を判断できるようにしてあります。

| コード | 意味 | よくある対処 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 入力エラー（URL/IDを特定できない） | watch / youtu.be / shorts 形式のURLか11字の動画IDを指定 |
| 3 | 動画メタ情報の取得失敗 | 動画が公開中か、URLが正しいか、ネットワークを確認 |
| 4 | 日本語字幕なし（`--asr never` 時）／字幕の取得・解析失敗 | 字幕のある動画を選ぶか、`--asr auto`（既定）で書き起こし分析を許可する |
| 5 | 音声の取得・変換失敗 | ffmpeg の導入を確認。`--player-client` の変更も有効な場合あり |
| 6 | 音声認識／F0解析の失敗 | faster-whisper の導入とモデル配置を確認 |

## 測定手法（出典と前提）

手法は既存の手作業ベンチマーク分析（赤ちゃんママの絵本の国・5本分析）と
同一の物差しになるよう設計し、その過程で以下を確定しました。

- **文分割**：字幕セグメントは文より粗いため、単語列から再構成する。
  単語の推定発話長モデル（0.13秒/字＋0.06秒/単語）で文末時刻を推定し、
  推定無音0.5秒以上を文の区切りとする（既存分析と同一ルール）。
- **単語時刻と文面の源**：優先順に (1) 字幕に含まれる単語単位の実時刻、
  (2) faster-whisper の単語タイムスタンプ（実音声の開始・終了時刻）、
  (3) `--asr never` 時の字幕ウィンドウ内分（近似）。
  日本語字幕自体がない場合は (2) の書き起こしが文面も担います
  （全文ASR経路。その場合はVADを無効化します）。
  現在の YouTube 字幕（json3/srv3/vtt）は単語時刻を含まない形式が通常で、
  実際には (2) が主経路になります。レポートの「方法」節に、どの経路で
  測ったかが必ず明記されます。
- **字数**：空白と句読点・記号を除いて数える（字幕文には句読点がなく、
  書き起こし文には付くため、基準を揃える）。
- **F0**：Praat（parselmouth）で10ms刻みに抽出。強度52dB超のフレームだけを
  声として採用（BGM対策のゲート）。統計は中央値中心、Hzの絶対値ではなく
  **半音単位の相対値**で扱う（声質の違う話者同士を比べるため）。
- **セリフ／地の文**：文のF0中央値の高さでクラスタ推定する
  （地の文＝全体中央値の±2半音以内、セリフ＝+4半音以上）。台本との
  照合はしていない推定値です。

## 既知の制約

- 日本語字幕（公式または自動）がない動画は、`--asr auto`（既定）では
  音声全体の書き起こしで測定できますが、文面は機械書き起こし由来に
  なります（`--asr never` では従来通り終了コード4）。
  とくに歌唱（歌詞）の書き起こし精度は低く、歌詞の取りこぼしや
  誤認識が残ります。文面ベースの指標（文長・文末分類など）は参考値、
  時刻・ピッチ系の指標が比較的信頼できます。
- 自動字幕・書き起こしには誤認識があり、文末分類など文面ベースの指標は
  参考値です。時刻・ピッチ系の指標は影響を受けにくい設計です。
- 間の秒数には±0.2〜0.3秒程度の誤差がありえます。
- BGMが大きい動画ではF0分布の裾（低い側・高い側）の信頼性が下がります。
- セリフ／地の文の判別はピッチ推定のみで、声色の違いは見ていません。
- YouTube側の仕様変更で字幕形式や取得方法が変わる可能性があります
  （その場合は yt-dlp の更新と本ツールの追随が必要です）。

# voice_adjust.py — キャラクリ方式の音声調整ツール（生成側）

video_analyzer.py（測定側）と対になる生成側ツールです。ゲームの
キャラクタークリエイト画面のように「トーンプリセット＋ステータス
（0〜100）」で声を選び、キャラシート（JSON）に保存して再利用できます。
あちらが測った「読みの型」（話速・間・ピッチ）を、生成音声へ数値で
反映します（製品ロードマップ Phase 2「分析→合成ループ」の第一歩）。

**製品原則（ボブ方針）: 「簡単な入口 × 細かいカスタム ＝
『この声が欲しかった』が売り」。** 入口は3ステップに絞り、奥には
数値で追い込む「上級調整」を正規に用意する二層構造です。

## かんたん3ステップ

1. **キャラを選ぶ**（`--preset リア` など、完成キャラが8つ）
2. **少しだけ調整する**（高さ・速さ・間・強弱の4つだけ。
   `--speed +10` のような相対指定も可）
3. **音声が出る**（WAV/MP3＋「目標 vs 実測」レポートつき）

調整結果は `--save-sheet` で「マイキャラ」として保存・再利用でき、
そこからさらに調整を重ねられます。

## 使い方

```bash
# プリセット（トーン／キャラ）とステータスの対応表を見る
python3 voice_adjust.py presets

# 【基本】キャラを選んで生成（エンジン既定は gemini）
python3 voice_adjust.py synthesize \
  --preset リア --text-file sample.txt --out-dir out/

# 【調整】プリセットを土台に、速さだけ +10 して、
# マイキャラとして保存（次回から --profile で再利用できる）
python3 voice_adjust.py synthesize \
  --preset リア --speed +10 --text-file sample.txt \
  --out-dir out/ --save-sheet my-ria.json --sheet-name リア・速めカスタム

# 【上級調整】数値を直接指定して追い込む（overrides に入る）
python3 voice_adjust.py synthesize \
  --profile my-ria.json --set-speed-cpm 400 --set-gap-sec 0.6 \
  --text-file sample.txt --out-dir out/

# お手本（video_analyzer の metrics.json）からキャラシートを作る
python3 voice_adjust.py make-sheet \
  --from-metrics test-output/gLv9_04OUyI/metrics.json \
  --out sheet-benchmark.json --tone 柔らかい

# キャラシートで音声を生成（WAV/MP3＋適用レポートが出る）
python3 voice_adjust.py synthesize \
  --text-file sample.txt --profile sheet-benchmark.json \
  --out-dir out/ --out-name voice
```

### プリセット → カスタム調整 → 保存の流れ

1. `--preset キャラ名` で土台のキャラシートを読み込む
2. 入口の調整: `--pitch/--speed/--gap/--expr` で4ステータスを
   上書き（絶対値 `60` でも、相対指定 `+10`/`-10` でも可）
3. 上級調整: `--set-speed-cpm/--set-gap-sec/--set-pitch-st` で
   数値を直接指定（overrides に入り、ステータス換算より優先）
4. `--save-sheet パス` で調整後のシートを別名のマイキャラとして
   保存（`--sheet-name` で名前指定。省略時は「キャラ名・カスタム」）
5. 次回からは `--profile マイキャラ.json` で読み込んで再利用・
   さらなる調整ができる

### ステータス（0〜100）

| ステータス | 実値への変換 |
|---|---|
| pitch（高さ） | ピッチシフト = (値−50)/50×6 半音（−6〜+6）。トーンのピッチ寄せを加算 |
| speed（速さ） | 目標話速 = 180＋値×3 chars/min（180〜480）。トーンの速さ寄せを乗算 |
| gap（間） | 文間の無音 = 0.2＋値/100×1.3 秒（0.2〜1.5） |
| expressiveness（強弱） | 0-33=控えめに淡々と／34-66=自然な抑揚／67-100=感情豊かに大きく抑揚を、とスタイルプロンプトへ反映（弱/中/強=20/50/80 でも指定可） |

- 微調整はキャラシートの `overrides`（数値の直接指定）がステータス換算
  より優先されます。`match_reference_pitch: true` にすると、お手本の
  F0中央値へ生成音声のピッチ中央値を寄せます（±6半音でクランプ）。
- 数値で担保しているのは話速・間・ピッチ中央値です。強弱とトーンは
  スタイルプロンプト経由のため再現保証はありません（レポートにも明記）。
- 話速は生成側・完成側とも VAD（無音を除いた発話時間）基準で測定
  します。文間の間は、文中のポーズと混ざらないよう「組み立て位置」
  （無音を挿入した箇所）で実測します。

## エンジン

- `gemini`：gemini-2.5-flash-preview-tts をサロゲート認証で直接呼ぶ
  （コネクタ custom.gemini-api と同方式。無料枠には日次クォータがあり、
  429 が返ったら時間をおくか local へ切替）。
- `local`：既存 tts CLI。声はキャラシートの `voice` に voice ID を指定
  （未指定だと男性声が既定。リア用は ID 指定が前提）。
