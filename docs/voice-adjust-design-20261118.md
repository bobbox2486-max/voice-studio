# voice_adjust.py 設計メモ（2026-11-18、ユイ）

## 目的・位置づけ
- ボブ指令「こっち側で調整できる仕組みを作れる？」への実装物。アミ報告（Gemini TTSの方向づけ＋テキスト調整＋お手本の型の数値化なら今でもある程度いける）を道具化する。
- 音声抽出システムの対になる「生成側」：video_analyzer.py が測った「読みの型」（話速・間・ピッチ）を、生成音声へ数値で反映する。製品ロードマップ Phase 2（分析→合成ループ）の第一歩。
- 置き場所：~/workspace/ria-study/tools/voice_adjust.py（video_analyzer.py と同居、単体CLI・同スタイル）。

## 製品原則（2026-11-18 ボブ方針、二度の微修正を反映）
**「簡単な入口 × 細かいカスタム ＝『この声が欲しかった』が売り」**
- 難しい道具は売れない。入口は「キャラを選ぶ → 大まかに調整 →
  音声が出る」の3ステップに絞る。
- ただしカスタムは細かくてよい。売れるポイントは「欲しかった声に
  たどり着けること」なので、overrides 等の数値指定は削らず、
  奥の「上級調整」として正規に残す（二層構造）。
- 調整の入口は「高さ・速さ・間・強弱」の4項目まで。専門用語や
  細かい数値は入口に出さない。

## できること（v1）
1. テキスト＋キャラシート（JSON）→ 調整済み音声（WAV/MP3）＋適用レポート（md）。
2. お手本取り込み：video_analyzer.py の metrics.json → キャラシート自動生成（make-profile）。
3. 調整項目：話速（発話内 chars/min）、文間の間（無音秒数）、ピッチシフト（半音、明示指定＋任意でお手本F0中央値へ寄せる）、トーン（Gemini TTSスタイルプロンプト）、エンジン（gemini / local=既存tts CLI）、声名。

## キャラクリ方式（2026-11-18 ボブ仕様追加）
ゲームのキャラクタークリエイト画面のように「選んで作る」方式にする。画面UIは将来で、v1はCLI＋キャラシートJSON。

### トーンプリセット（名前で選ぶ）
各プリセットは「Geminiスタイルプロンプト／推奨の声／ピッチ寄せ（半音）／速さ寄せ（倍率）」のセット。

| プリセット | スタイルプロンプト（要旨） | 推奨voice | ピッチ寄せ | 速さ寄せ |
|---|---|---|---|---|
| 明るい | 明るく爽やかに、笑顔が伝わるように | Leda | +1.0 | ×1.00 |
| 柔らかい | 柔らかく優しく、包み込むように | Aoede | 0.0 | ×0.95 |
| 元気 | 元気いっぱいに、はつらつと | Zephyr | +0.5 | ×1.05 |
| 落ち着いた | 落ち着いて穏やかに、ゆったりと | Callirrhoe | −1.0 | ×0.92 |
| クール | クールにさらっと、感情は抑えめに | Autonoe | −1.5 | ×0.98 |
| 甘い | 甘く可愛らしく、親しみを込めて | Kore | +1.5 | ×0.97 |
| カスタム | style_prompt を自分で書く | 自由 | 0.0 | ×1.00 |

### ステータス（0〜100のスライダー値で選ぶ）
| ステータス | 対応する実値 | 変換式 |
|---|---|---|
| pitch（高さ） | ピッチシフト半音 | (値−50)/50×6 → −6〜+6半音。これにトーンのピッチ寄せを加算 |
| speed（速さ） | 目標話速 chars/min | 180＋値×3 → 180〜480 |
| gap（間） | 文間の無音 秒 | 0.2＋値/100×1.3 → 0.2〜1.5秒 |
| expressiveness（強弱） | スタイルプロンプトの抑揚指示 | 0〜33=控えめに淡々と／34〜66=自然な抑揚で／67〜100=感情豊かに大きく抑揚を。弱/中/強 の指定も可（=20/50/80に変換） |

- 強弱は後処理では作れない（ピッチ幅の加工はv1対象外）ため、主にスタイルプロンプトへ反映する。数値担保の対象外であることをレポートにも明記する。
- 微調整用に overrides（数値の直接指定）が使える。overrides があればステータス換算値より優先する（キャラシートは「選んだ値」と「実効値」の両方を保持する）。

### プリセット → カスタム調整 → 保存（フロー）
1. `synthesize --preset キャラ名` で土台シートを読み込む
2. 入口の調整 `--pitch/--speed/--gap/--expr`: 絶対値（`60`）でも
   相対指定（`+10`/`-10`）でも上書きできる
3. 上級調整 `--set-speed-cpm/--set-gap-sec/--set-pitch-st`:
   overrides へ数値を直接指定（ステータス換算より優先）
4. `--save-sheet パス`（＋任意で `--sheet-name`）で調整後シートを
   「マイキャラ」として別名保存し、次回 `--profile` で再利用する
5. プリセット使用時は調整後シートの控えを出力先に sheet-used.json
   としても残す

## パイプライン
1. 前処理：空白正規化→文分割（。！？!?と改行を境界、句読点は文末に保持）。文字数は video_analyzer と同じ基準（空白・句読点を除く）で数える。
2. 生成：文ごとにTTS。
   - gemini：gemini-2.5-flash-preview-tts をサロゲート認証で直接呼ぶ（コネクタ custom.gemini-api と同じ方式。ヘルパーはテキスト抽出専用なので音声はこちらで実装）。スタイルプロンプトは読み上げテキストの先頭に指示文として付ける（2026-11-17試作で実証済みの方式）。応答は PCM 24kHz/16bit/mono → WAV化。
   - local：既存 tts CLI（/opt/hatch/bin/tts）に文ごと依頼し MP3→WAV変換。声はプロファイルの voice（ID）をそのまま渡す。
3. 実測（生成直後）：全セグメントの発話時間合計から素の話速を算出。
4. テンポ調整：atempo（ピッチ保持）で目標話速へ。係数 = 目標話速 / 素の話速（atempoは再生速度の倍率なので、遅くしたいときは1未満）。0.5〜2.0にクランプし範囲外は警告。話速は生成側・完成側ともVAD（無音を除いた発話時間）基準で測る——初回テストで物差しが違うと比較にならないことを実測で確認した。
5. ピッチ調整：rubberband=pitch（テンポ保持）。シフト量 = プロファイル pitch_shift_st ＋（match_reference_pitch=true のとき）お手本F0中央値と生成音声F0中央値の差（±6半音にクランプ）。生成音声のF0は parselmouth で測定（video_analyzer と同じ物差し）。
6. 間挿入：目標秒数の無音WAVを文間に挟み、WAVフレーム単位で結合（全セグメント 24kHz/mono/16bit に正規化済み前提）。
7. 測定・検証：完成音声を再測定——発話/無音の走査（10ms RMS）で実話速・間の中央値、parselmouthでF0中央値。目標 vs 実測をレポートに表で出す。
8. 出力：out.wav / out.mp3 / report.md / profile-used.json（適用したプロファイルの控え）。

## キャラシート形式（JSON）＝プロファイル
```json
{
  "name": "キャラ名（シートの名前）",
  "tone_preset": "明るい | 柔らかい | 元気 | 落ち着いた | クール | 甘い | カスタム",
  "style_prompt": "カスタム時のみ使うトーン指示文（プリセット時は空でよい）",
  "stats": {"pitch": 50, "speed": 50, "gap": 50, "expressiveness": 50},
  "overrides": {"target_speed_cpm": null, "target_gap_sec": null, "pitch_shift_st": null},
  "engine": "gemini | local",
  "voice": "Leda（空ならプリセットの推奨voiceを使う。localでは tts の voice ID）",
  "match_reference_pitch": false,
  "reference_f0_median_hz": 217.6,
  "source": {"type": "metrics", "video_id": "...", "title": "..."}
}
```
- 実効値の決まり方：トーンプリセット＋ステータス換算 → overrides があれば上書き → match_reference_pitch の差分をピッチに加算。
- make-profile（お手本取り込み時）：target_speed_cpm は metrics の captions.speed_speech（発話内速度）を採用（speed_overall は間込みなので生成側の物差しに合わない）。target_gap_sec は captions.gap_median（場面転換の大間も混ざるが中央値なので文間の代表値として使う。READMEに明記）。この2つは overrides に数値で入れ、ステータスは逆換算して表示用に埋める。reference_f0_median_hz は f0.median_hz。

## エラー方針（video_analyzer と同じ流儀）
- 終了コード：2=入力・引数エラー、3=ネットワーク/APIエラー、4=生成・処理エラー、5=測定エラー。
- メッセージは日本語＋「どうすれば直るか」を必ず添える。APIキーの値は一切出力しない。

## テスト計画
1. make-profile：基準動画 gLv9_04OUyI の metrics.json → speed≈341.3 / gap≈0.74 / ref F0≈217.6 が入ること。
2. synthesize（gemini）：短文3文＋キャラクリ指定（トーン=明るい、speed stat 40→300cpm、gap stat 46→0.8秒、pitch stat 58＋明るい寄せ+1→約+2半音）で1本生成。実測が 速度±10% / 間中央値±0.15秒 / F0シフト（無調整の生成と比較）+2±1.5半音 に入ること。ピッチ後処理そのものの精度は、生成済みセグメントへ rubberband を掛けて前後F0差を測る方法でも別途確認する。
3. synthesize（local）：1文だけ実行し、経路が通ること（声の検証は対象外）。
4. 異常系：存在しないプロファイル、空テキスト、metricsでないJSON → コード2で対処付きメッセージ。

- make-sheet：基準動画の値（341.3／0.74／217.6）を正確に取り込み OK。
- 話速：当初2回失敗（①物差しの不一致＝生成側は全体長・完成側はVADで測っていた、②atempo係数の向きが逆）。両方直して、オフライン再構成で 299 vs 目標300（誤差0.4%）を確認。
- 間：セグメント前後の無音トリム＋「組み立て位置での実測」に変えて 0.86 vs 目標0.80（許容±0.15内）。
- ピッチ：rubberband で +1.89半音 vs 指定+1.96。正確。
- local経路：話速337 vs 330、間0.92 vs 0.85 で OK。
- 異常系4件：全てコード2＋対処付きメッセージ。
- 未完：Gemini通し再テストは無料枠クォータ429で中断。後処理チェーンは生成済みセグメントで検証済み。クォータ回復後に通し確認が残課題。

## v1の限界（正直メモ）
- 文単位の生成なので、文をまたぐ抑揚のつながりは再現しない（Phase 2の課題）。
- Gemini TTSのスタイル指示は確率的で、トーンの数値保証はできない。数値で担保できるのは速度・間・ピッチ中央値まで。
- ピッチの「お手本寄せ」は中央値合わせのみ。抑揚カーブ自体の移植はしない。
- 既存TTS（local）は外国なまり等の品質上限が従来通り。調整の土台としてのみ使う。
